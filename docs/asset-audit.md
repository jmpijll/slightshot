# Cross-platform asset audit

Audited after merging PRs #4, #5 and #6, at main revision `2c6eacca3fe4fbbd8d9be379577d3ef247c8d668`.

The current Mac appearance is the design reference. The main portability problem is the toolbar icon set: Mac asks the OS for SF Symbols, while Windows draws its own approximations. Shared geometry would remove this difference without changing toolbar layout or interaction.

## Shared icon proposal

Start with the 13 product glyphs: Pen, Line, Arrow, Rectangle, Marker, Text, Undo, Print, Copy, Save, Close, Record and Stop. Draw original vectors rather than exporting or tracing Apple symbols. Use the current Mac toolbar as the visual reference: compact icons, consistent medium line weight, round joins/caps, centred optical alignment and white tint.

Keep 30-point buttons, 6-point button corners, 9-point panel corners, 4-point panel padding, 2-point button spacing, current hover/selected states and the red recording accent. The colour well remains its own control. Put canonical icon geometry in one repository-owned source and generate or load both AppKit and WPF representations from that source; do not retain two manually maintained icon sets.

Ship this as a separate reviewable PR. Show before/after Mac toolbar captures and native Windows fixtures on the same clean background. Include normal, hover, selected, disabled, Record and Stop states at 1× and 2×. Check that every icon renders, is unclipped, retains its accessibility label and does not move any control. Review visual changes before merging this new PR.

The asset change should not replace native Mac blur or redesign Settings/file dialogs. Those are separate decisions, and the existing Mac appearance is already the user's preferred reference.

## Platform restrictions

Apple's [Xcode and Apple SDKs Agreement](https://www.apple.com/legal/sla/docs/xcode.pdf), section 2.10, restricts Apple-owned system-provided images to applications for the corresponding Apple-branded platforms. Consequently, exporting SF Symbols and bundling them with the Windows app is not the proposed solution. Original shared artwork avoids reliance on that OS asset library.

The project logo is already drawn from project-owned points in `Scripts/make_icon.swift`; it is not an SF Symbol. The Mac tray fallback does not change the provenance of the normal shipped logo.
